# Manuscript Export Pipeline

Gabriel writes *String Theory* in Apple Pages. Everything downstream — the Google Drive export set, the GitHub Pages chapter index, the EPUB — is generated automation, not separate authoring surfaces. This article documents the pipeline so any agent (Claude, ChatGPT/Atlas, Gemini, Cursor) resolves manuscript requests to the right layer instead of guessing.

Source of routing truth: `manuscript-manifest.md` (Google Drive, `string-theory` folder, id `1wlqXNvolIuspqA-_OXLuj1wlPSriVfUY`), which records its own correction history below. Technical pipeline details sourced from `watch_manuscript.py` (Drive, id `1FOBzU2I1-nfmvFgFKGknyGYWc_5M6Qgw`).

## The pipeline

1. **Pages (authoring surface).** Gabriel writes and edits the manuscript here. This is the only place prose is actually composed.
2. **Google Drive sync → Manuscript Masters.** Pages exports land in `/Users/gabrielmcp/Library/CloudStorage/GoogleDrive-gabemcpherson@gmail.com/My Drive/Manuscript Masters` as `String Theory - Draft <version>.docx` (and paired `.txt`/`.pdf`). This is a synced folder, not a manual upload step.
3. **`watch_manuscript.py` (daemon).** Runs a `watchdog` `PollingObserver` against the Manuscript Masters directory, polling every 2s. Polling (not `FSEvents`) is required because Google Drive's macOS FileProvider extension, and Pages' safe-save behavior, write to a temp path and atomically swap — a pattern that bypasses native filesystem events. On detecting a change to the target `.docx`, it debounces for 5 seconds of quiet, then shells out to `rebuild_and_deploy.sh`.
4. **`rebuild_and_deploy.sh`.** Lives at `Manuscript Masters/string-theory-chapters/rebuild_and_deploy.sh` — inside a git-tracked subfolder of the synced Drive folder. Regenerates the exported text/doc/pdf/epub set and the GitHub Pages chapter HTML, then pushes to `github.com/Gabrielmcp78/string-theory-chapters`.
5. **GitHub Pages (`gabrielmcp78.github.io/string-theory-chapters`).** The public/browsing exposure. Serves the chapter index, per-chapter HTML pages, `manifest.json`, and the full EPUB download.

Verified working end-to-end 2026-07-08: `Draft 6.7.docx`/`.pdf` in Manuscript Masters both carry `createdTime`/`modifiedTime` of 2026-07-08T19:30–19:48Z; the GitHub Pages index footer reads "Built 2026-07-08" with matching content (Prologue/Chapter 1 text is identical across the Drive `.pdf` and the live site). The pipeline is live infrastructure, not a documented-but-unverified design.

## Canonical retrieval hierarchy for agents

This is the routing logic from `manuscript-manifest.md`, which itself evolved through several corrections — included here so the reasoning isn't lost, only the current conclusion:

1. **First instinct (superseded):** treat the GitHub Pages HTML index as canonical. Wrong — it's a derived browsing layer generated by the same automation, not the master.
2. **Correction:** the canonical **current text** lives in `Manuscript Masters` as Pages' direct export — prefer the `.txt` export for exact prose retrieval; use `.docx`/`.pdf` only for formatting/layout checks.
3. **Refinement (current model — paired layers, not a single source):**
   - **Drive `Manuscript Masters` exports** (`.txt` preferred) = canonical text for exact prose.
   - **GitHub Pages HTML** = the structured navigation/manifest layer — chapter titles, scene boundaries, paragraph counts, word counts — genuinely superior for *locating* content, just not authoritative for the prose itself.
   - Practical rule: don't choose one over the other. Use GitHub HTML to find the scene/chapter boundary, then pull exact text from the Drive export.
4. **Explicitly excluded from the normal sequence:** native Google Docs reading (`drive.read_doc` or equivalent). The authoring workflow is Pages, not Google Docs — Docs-native structure can introduce wrong routing and isn't part of this pipeline.
5. **SB (this KB) raw files and wiki summaries are never manuscript text.** Archival fallback / historical comparison only.
6. **No user workarounds.** Agents must not ask Gabriel to paste direct chapter URLs. For a request like "Chapter 20 Scene 5," resolve chapter/scene boundaries via the GitHub HTML manifest, then retrieve exact text from the Drive export — trying index reads, known URL patterns, or manifest search before ever asking Gabriel to compensate for a tooling gap.

**Manuscript prose remains read-only for every agent** regardless of which layer is being read from, per `DECISION-2026-06-10-manuscript-read-only` — this pipeline governs *retrieval*, not editing authority.
