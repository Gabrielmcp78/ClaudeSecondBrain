# Rewrite Authorization Protocol

Use before changing manuscript prose or creating revised prose that might be mistaken for source.

## Authorization levels

- Discuss only: answer questions, explain risks, summarize status.
- Diagnose: critique or assess without changing prose.
- Plan: make a revision plan, beat map, or edit list without new prose.
- Draft experiment: create noncanonical exploratory prose.
- Surgical revision: revise a clearly bounded passage or scene.
- Assembly: integrate approved material into a canonical or working manuscript file.
- File-control update: change status/metadata in a control index.

## Required before drafting or revising

Confirm all of the following:

- target project
- exact chapter/scene/passage
- source text to use
- desired operation
- whether the output is canonical, experimental, or recommendation only
- whether any live document should be modified

## Interpretation rules

- A critique attachment is not rewrite authorization.
- A request for a readiness judgment is not rewrite authorization.
- `Proceed` depends on the immediately preceding proposed action; do not extend it to assembly or canonization.
- `Green light to get it done` authorizes the named documentation/control task in context, not manuscript prose changes.
- If user asks for a `draft experiment`, label it draft experiment only.

## Output labeling

Every revised-prose output should include:

- project
- chapter/section range
- pass type
- source used
- canon status
- date
- whether word/count scope was verified

## Stop conditions

Stop and ask or verify if:

- source text is missing
- requested scope is ambiguous
- canonical versus experimental status is unclear
- two files conflict
- the user seems to expect a live edit but no exact target is confirmed
