# Source Authority and Drift Control

This note defines the control plane agents should use before taking action.

## Source authority classes

- Canonical manuscript: approved source prose. Read before quoting, revising, summarizing, or judging current canon.
- Experimental draft: noncanonical exploratory prose or options material. May be useful, but must remain labeled experimental until explicitly approved.
- Approved - Not Assembled: approved working artifact that has not been merged into the canonical manuscript. Do not treat as canon or assemble without explicit instruction.
- Visual companion: design, Canva, map, board, or other reference aid. Never source prose unless explicitly stated.
- Secondary critique/reference: editorial critique, summary, beat outline, prior answer, or SecondBrain note. Helpful context, not manuscript source.
- Submission artifact: packaged or cleaned reading draft prepared for a purpose. Must not silently replace canonical source.

## Drift controls

- Do not infer missing bridge material, chapter status, or latest revision state.
- Do not normalize names, spellings, or terminology without authorization.
- Do not collapse experimental and canonical layers.
- Do not let critique language become prose by accident.
- Do not judge submission readiness before separating accidental scaffold labels from manuscript text.

## Minimum verification before action

For any substantive project task, record:

- active project
- source file or Drive file used
- artifact class
- date/modified time if available
- user-authorized operation
- output created or updated
- unresolved verification gaps

## Known recurring risks

- STRING THEORY: experimental/options material can be mistaken for canonical Draft 6.7.
- STRING THEORY: reading drafts and cleaned submission artifacts can be mistaken for source authority.
- BURNThrough: approved working artifacts can be mistaken for assembled canon.
- BURNThrough: incomplete overview material can be mistaken for a complete canon bible.
- File control: uploaded Office sheets cannot always support live Google Sheets updates; native Sheets are required for reliable live control.
- Tools: Chrome/browser read context does not imply Google Docs write access; write-capable tools do not imply edit authorization.
